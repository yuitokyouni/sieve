3 · How to read this

  • REGRESSION — A passed the reference gate, B fails it.
  • IMPROVEMENT — A failed, B passes. Never blocks approval.
  • CHANGED_WITHIN_GATE — the distribution moved but both versions sit on the same side of the reference gate; the reference test alone would not have noticed. Needs a human judgment: intended or not?
  • STABLE — no detected move, gate statuses unchanged.
  • NOT_SEPARATED — no detectable difference at this line with this many windows. Not a claim of equality.

4 · Caveats

  • the A-vs-B null is a permutation over windows, valid for exchangeable window sets; windows cut from one long simulated path share that path
  • measured family-wise false-positive rate of this design under H0 (same parameters, independent seeds): 0.005 at 15v15 windows (n=400 pairs), 0.0 at 6v6 (n=200) — conservative relative to the nominal alpha (docs/compare-calibration.json, tools/calibrate_compare.py)
  • measured power boundary: persistence drifts of |delta beta| <= 0.04 are mostly undetected at 15v15 windows, and a tail-df clip alone at high persistence is nearly invisible to unconditional window statistics (docs/compare-calibration.md)
  • NOT_SEPARATED means no detectable difference at the alpha=0.01 line with this many windows — it is not a claim of equality
  • the approval outcome is a versioned routing rule over required dimensions, not an aggregate; verdicts remain per-metric
